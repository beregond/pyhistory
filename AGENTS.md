# AGENTS.md

## Overview
PyHistory: CLI (`pyhistory`, alias `pyhi`) that keeps changelog entries as per-entry fragment files in `history/` (no merge conflicts) and compiles them into `HISTORY.rst`/Markdown on release. Python package under `src/`, built with hatchling + versioningit. Runtime deps: `click`, `toml`. Supported Python: 3.11-3.15 (`requires-python = ">=3.11"`).

## Layout
- `src/pyhistory/cli.py` - click entry point (`pyhistory.cli:main`)
- `src/pyhistory/pyhistory.py` - core history logic
- `src/pyhistory/file_config.py`, `utilities.py`, `exceptions.py` - config, helpers, errors
- `src/pyhistory/_version.py` - generated by versioningit (gitignored; do not edit)
- `src/tests/` - pytest tests (+ `fixtures/`)
- `docs/` - Sphinx with furo theme (`conf.py`, `requirements.txt` used by Read the Docs)
- `history/` - pending changelog fragments, one file per entry, committed with the change; `HISTORY.rst` - compiled changelog (`[tool.pyhistory]` in pyproject)
- `.github/workflows/test.yml`, `.github/workflows/release.yml`, `.readthedocs.yaml`

## Conventions
- Changelog: this repo dogfoods its own tool. Every user-visible change (incl. supported Python versions) gets an entry added with `pyhi add "Message."` (alias of `pyhistory`; run from the repo root, after `pip install -e .`). It writes a fragment file into `history/`; `git add` it with the change.
  - Never write raw entries into `HISTORY.rst` and never create/edit `history/` files by hand.
  - Check pending entries with `pyhi list`; remove one with `pyhi delete`.
  - `pyhi update <version>` compiles fragments into `HISTORY.rst` at release time - only the maintainer runs it.
  - Style: past tense, one sentence, trailing period, e.g. "Added support for python 3.15."
- Use `X | None` (not `typing.Optional`), builtin generics (`list[str]`) and `collections.abc` types; ruff UP035/UP045 enforce this.
- No ruff config: ruff defaults, same as CI (CI installs the latest ruff, so new default rules can appear without code changes).
- Tests live in `src/tests/`; no tox/setup.py.

## Commands
- Setup: `python -m venv .venv && .venv/bin/pip install -e '.[dev]' ruff build`
- Test: `pytest --cov .` (CI) or `pytest -q`
- Min-version check: `uv run --no-project --python 3.11 --with pytest --with-editable . pytest -q` (creates `uv.lock`; delete it, do not commit)
- Lint: `ruff check .`; format check: `ruff format --check .` (both must pass)
- Build: `python -m build` (sdist + wheel, no warnings); output in `dist/` (gitignored)
- Docs: `pip install -e '.[docs]'` then `sphinx-build -W -b html docs docs/_build/html`. Theme is furo (same as jsonmodels); keep `docs/requirements.txt` and the `docs` extra in `pyproject.toml` in sync. `docs/readme.rst` pulls in `README.md` via `sphinx_mdinclude`, so CLI examples and config live in README; `docs/usage.rst` is a short workflow + command overview.
- Local docs preview: `serve-docs [PORT]` (`devbin/serve-docs`, on PATH via direnv `.envrc`). Uses `.venv` if present, installs the `docs` extra if missing (pip, or `uv pip` for uv venvs), builds into `docs/_build/html` and serves on http://localhost:8000 (default port).

## CI / Docs hosting
- `.github/workflows/test.yml`: triggers on `pull_request` only. Job `build`: matrix Python 3.11-3.15, `pip install .[dev]`, `pytest --cov .`. Job `lint`: `astral-sh/ruff-action`.
- Action versions: `actions/checkout@v7`, `actions/setup-python@v7`, `astral-sh/ruff-action@v4.1.0` (v4 uses node24 runtime). ruff-action publishes NO floating major tag (`@v4` fails to resolve) - always pin the full version; check with `git ls-remote --tags https://github.com/astral-sh/ruff-action.git`.
- `.github/workflows/release.yml` (same as jsonmodels): runs on any pushed tag, only in `beregond/pyhistory`. Builds sdist + wheel (`python -m build`, `twine check`), checks the built files carry exactly the tag's version (version comes from the git tag via versioningit, there is no static version in `pyproject.toml`), then uploads to PyPI with trusted publishing (`pypa/gh-action-pypi-publish@release/v1`, GitHub environment `pypi`, `id-token: write`; no API token). Requires a trusted publisher configured on pypi.org for this repo/workflow/environment.
- Release steps (maintainer): `pyhi update <version>`, commit, `git tag <version>` (no `v` prefix, matching existing tags), push the commit and the tag.
- `.readthedocs.yaml`: ubuntu-24.04, Python 3.14, `docs/conf.py`, deps from `docs/requirements.txt`.

## Gotchas
- Baseline: 43 tests pass (99% coverage) on 3.11, 3.14 and 3.15.
- `ruff check .` and `ruff format --check .` must both pass (CI lint job). Default rules in recent ruff include isort (I001), pyupgrade (UP), bugbear (B), simplify (SIM) and ISC - run `ruff check --fix . && ruff format .` before pushing.
- Docs build cleanly with warnings as errors (`sphinx-build -W`).
